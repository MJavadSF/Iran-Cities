# Contributing

Thanks for helping. Most contributions to this project are data corrections, so this guide starts there.

## Reporting a data error

Open a [data correction issue](https://github.com/MJavadSF/Iran-Cities/issues/new?template=data-correction.yml). Please include a **source** for the correct value: an official page (Statistical Centre of Iran, a provincial governorate, the Ministry of Interior), Wikipedia with its references, or a map link for coordinates. Reports without a source can't be merged, because every value in the package has to be verifiable.

## Changing the data yourself

All data lives in [`src/data.json`](./src/data.json). Everything else (the packed files, CSV, SQL, the lite build) is generated from it.

1. Edit `src/data.json`. Keep ids unchanged: an id is never reused or renumbered. A new city gets the next free id.
2. If you rename a city's English id, add the old slug to `legacy-slugs` so existing links keep working, and add an entry to `src/changes.ts`.
3. Run `npm run validate`. It checks ids, slugs, capitals, area codes, coordinates, aliases and neighbors.
4. Run `npm test`. One test checks that every coordinate lies inside its own province's boundary.
5. Add a line to `CHANGELOG.md` and open a pull request.

## Changing the code

```bash
npm install
npm test               # data validation, types, lint, unit tests
npm run test:coverage  # with coverage thresholds
npm run build          # build the package
npm run test:dist      # smoke test of the built package
```

The development tools need Node.js 22.18 or newer. The published package must keep working on Node.js 14, TypeScript 3.9 and React 16.8, so don't use newer runtime APIs in `src/` without checking CI.

Code style:

- No comments in the code. Make names and structure explain the code instead.
- Public functions need explicit types (`isolatedDeclarations` is on).
- Data that is shared must stay frozen; functions that return new arrays must keep doing so.

## Changelog

Describe every change that affects the published package under an `## Unreleased` heading at the top of `CHANGELOG.md`: fixes and data corrections, new features, and breaking changes. The maintainer turns it into a version number when publishing.

## Boundaries and neighbors

`src/boundaries.json` and the `neighbors` field are generated by `scripts/geo/build-boundaries.py` (Python 3 with `shapely` 2.x). The boundary data comes from geoBoundaries (OpenStreetMap, ODbL 1.0); see [`NOTICE.md`](./NOTICE.md).

## Code of conduct

Be kind and assume good intent. Harassment of any kind is not accepted.
